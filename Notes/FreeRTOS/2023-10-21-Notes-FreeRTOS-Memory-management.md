# 内存管理

在嵌入式系统中，标准 `malloc` 和 `free` 可能存在以下限制，具体取决于所用 libc、分配器实现和配置：

- 精简运行库不一定提供动态内存分配功能。

- 引入分配器可能增加代码体积，需要结合链接结果评估。

- 不一定提供多任务安全保证；需要确认运行库的重入和加锁机制。

- 分配和释放耗时可能随空闲块分布而变化，需要评估最坏执行时间是否符合实时预算。

因此 **FreeRTOS** 将内存分配的接口放置在了可移植层中，而除了 5 种默认的内存管理方案，用户也可以自由定制针对特定硬件的内存方案。

## 内存管理方案

工程通常只选择一套 `pvPortMalloc` / `vPortFree` 实现。

| 方案 | 可释放 | 合并相邻空闲块 | 多个非连续区域 | 初始化与内存来源 |
| --- | --- | --- | --- | --- |
| heap_1 | 否 | 不适用 | 否 | 使用 `ucHeap`，容量由 `configTOTAL_HEAP_SIZE` 指定 |
| heap_2 | 是 | 否 | 否 | 使用 `ucHeap`，首次分配初始化空闲表 |
| heap_3 | 是 | 由 libc 决定 | 由 libc 决定 | 使用 libc 的堆及其初始化机制 |
| heap_4 | 是 | 是 | 否 | 使用 `ucHeap`，首次分配初始化空闲表 |
| heap_5 | 是 | 是 | 是 | 首次分配前调用 `vPortDefineHeapRegions` |

`heap_1/2/4` 的 `ucHeap` 可以由实现内部定义，也可以在 `configAPPLICATION_ALLOCATED_HEAP = 1` 时由应用提供；`heap_3/5` 不以 `configTOTAL_HEAP_SIZE` 定义所管理的堆容量。

### `heap_1.c`

最简单的内存管理方案，但不允许在分配了内存后释放内存。

### `heap_2.c`

允许释放已经分配的块，但它不会将相邻的空闲内存块组合成一个更大的空闲内存块。建议用 `heap_4.c` 来替代。

### `heap_3.c`

简单封装 `malloc` 和 `free`，通过 `vTaskSuspendAll` / `xTaskResumeAll` 防止使用该封装的任务在分配或释放期间相互切换。这不屏蔽中断，也不为绕过封装直接调用 libc 的代码提供同样的互斥保证。

这些普通动态分配接口不是 ISR 安全接口；中断处理程序不应调用它们。可在任务中预先分配缓冲区，或由 ISR 通知任务完成需要分配内存的工作。

### `heap_4.c`

允许释放已经分配的块，也会将相邻的空闲内存块组合成一个更大的空闲内存块。对于大部分应用都推荐使用该方案。

### `heap_5.c`

使用 `heap_4.c` 中的合并算法，由一个分配器管理多个非连续内存区域，因此可以同时覆盖内部和外部 RAM。分配器按地址顺序查找能容纳请求的空闲块，不会按内存快慢或对象类型自动路由；有指定存储位置要求时，需要应用另行选择分配策略。

必须在第一次 `pvPortMalloc` 之前调用一次 `vPortDefineHeapRegions`，也就是在创建任何需要动态分配的任务、队列等对象之前完成定义。传入的 `HeapRegion_t` 数组按区域起始地址从低到高排列，区域不得重叠，并以起始地址为 `NULL`、大小为 0 的项结束。各区域须留出对齐和管理结构的空间；一次分配不能跨越不连续区域之间的空洞。

## 分配失败与容量观察

调用 `pvPortMalloc` 后必须检查是否返回 `NULL`；创建内核对象也应检查其句柄或状态码。启用 `configUSE_MALLOC_FAILED_HOOK = 1` 后，默认方案在分配失败时调用应用提供的 `vApplicationMallocFailedHook`。钩子用于记录或执行既定故障策略，不会自动回收空间，也不能代替调用方的失败处理。

生命周期固定的内核对象可以在 `configSUPPORT_STATIC_ALLOCATION = 1` 时使用相应的静态创建接口，由应用提供对象和栈等存储，减少对运行期动态分配的依赖。

- `heap_1/2/4/5` 提供 `xPortGetFreeHeapSize`，用于观察当前总空闲量；总空闲量足够不代表存在能满足请求的连续块，还需考虑对齐和块管理开销。
- `heap_4/5` 还提供 `xPortGetMinimumEverFreeHeapSize`。在完成堆初始化后的同一统计口径下，初始可用量减去历史最低空闲量，可估计分配器占用峰值；这不是用户有效载荷的精确总量。
- `heap_4/5` 的 `vPortGetHeapStats` 提供最大/最小空闲块、空闲块数及分配/释放次数等信息。结合总空闲量与最大空闲块观察碎片；合并只能连接相邻空闲块，不能消除仍被已分配块隔开的空洞。
- `heap_3` 的容量和碎片统计需要依赖所用 libc 或应用自身的记录，不能假定它实现了上述 FreeRTOS 堆统计接口。
