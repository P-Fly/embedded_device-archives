# 调度器的挂起

如果任务需要连续执行一段操作，又希望中断仍能得到处理，可以通过挂起调度器防止任务上下文切换。当前任务不会被其他任务换出，但仍可能被 ISR 打断。

挂起期间其他任务即使满足运行条件也不能立即执行，因此操作的最坏执行时间必须有界，并符合应用对任务响应时延的实时预算。持续较长的操作还会积累待处理 tick 和待就绪任务，增加恢复调度器时的处理开销，不能只计算操作本身的耗时。

## `vTaskSuspendAll`

### 功能

在不禁用中断的场景下挂起调度器，此时不会发生上下文切换。

调用可以嵌套：每次 `vTaskSuspendAll` 增加 `uxSchedulerSuspended`，每次 `xTaskResumeAll` 减少它，只有计数回到 0 才真正恢复调度。调用必须成对，包括错误返回等退出路径；这组接口用于任务上下文，不应从 ISR 调用。

挂起调度器不等于临界区，不会屏蔽 ISR，也不能单独保护任务与 ISR 共享的数据。中断仍可在符合优先级限制时调用相应的 `FromISR` 接口；与 ISR 的互斥需要另外采用适合该数据和端口的同步方式。

需要注意也不能在该状态下调用可能导致上下文切换的函数，比如 `vTaskDelay`、`vTaskDelayUntil`、`xQueueSend` 等。

即使把队列操作的等待时间设为 0，也不能据此认定这些 API 在挂起区间内可调用；不阻塞不等于不会唤醒其他任务或请求切换。应用应遵守各 API 的调用约束，不能仅根据内核内部也使用挂起调度器来组合调用。

### 原型

```c
void vTaskSuspendAll( void );
```

## `xTaskResumeAll`

### 功能

恢复调度器。

只有最外层的配对恢复才处理挂起期间推迟的调度工作。挂起时，tick 中断仍可发生，但正常 tick 推进由 `xPendedTicks` 记录后延迟处理；恢复时逐次补处理这些 tick，并处理相应的延时到期任务。

需要注意该函数不会恢复由 `vTaskSuspend` 挂起的任务。

### 原型

```c
BaseType_t xTaskResumeAll( void );
```

### 返回值

- `pdTRUE`：恢复调度器的处理已经引发了上下文切换，调用方不必再为该次待处理切换额外让出处理器。待就绪的高优先级或同优先级任务、补处理 tick 等都可能产生切换需求。
- `pdFALSE`：该次调用没有因恢复调度器而引发上下文切换，并不表示恢复失败。嵌套计数尚未归零时也会返回 `pdFALSE`，此时调度器仍挂起。
